# 翻正奖励对照与平滑性诊断

## 范围

本工具只评估当前训练环境，不修改奖励、模型、参考时序或 PPO 参数。
直接参考策略由训练环境自己的参考生成器和状态机推进，不运行另一套手调状态机。
旧 checkpoint 在当前配置下重评估，不等价于复现其原训练环境。

## 使用

在项目根目录运行三组基础对照：

```powershell
uv run python -B -m mjlab.scripts.Backup.baseline_trivial_policy --num-envs 16 --seeds 42 43 44 --cases zero random reference
```

增加指定策略的确定性与随机采样对照：

```powershell
uv run python -B -m mjlab.scripts.Backup.baseline_trivial_policy --num-envs 16 --seeds 42 43 44 --cases zero random reference trained sampled --checkpoint logs/rsl_rl/SQuRo_Backup/2026-09-11_16-51-44/model_2999.pt
```

- `--time-scale 3`：固定动作时间缩放。
- `--curriculum-iteration 0`：冻结所有策略的奖励课程轮次，不从 checkpoint 隐式继承。
- `--episodes-per-env 1`：每个种子、每个并行环境接收一个完整回合；可增大。
- `--random-amplitude 1`：随机动作 U(-1,1)，对应目标偏移 ±0.3 rad，并非全动作范围探索。
- `--output-dir logs/backup_evaluation`：默认生成带唯一时间戳的目录和 `evaluation.json`。
- 不启动 W&B、训练或可视化。评估目录必须可写；受限环境可指定其他输出目录。

## 公平性与统计口径

1. 所有策略使用相同环境、种子列表、动作缩放、动作裁剪、奖励与终止条件。
2. 每个并行环境只收首个完整 episode；其结束后自动重置产生的后续数据不参与统计。等慢环境结束后才开始下一轮，避免短回合采样过多。
3. 先累计最后一步，再保存 episode；`terminated | truncated` 均计入完成。
4. 奖励分项从 RewardManager 的逐步加权奖励率获取，再按其配置乘 dt；不对 `Episode_Reward/*` 日志进行逐步累加。
5. 每步校验分项之和与环境返回奖励一致；保存总回报、折扣回报、逐项贡献、每秒回报以及成功/失败分组。
6. 利用 Recorder 的重置前回调保留终止步状态，避免读取到下一回合初态。
7. S1/S2 到达按训练阶段实际推进计数，不用全环境平均日志推算成功率。阶段奖励按动作下发前阶段归属，里程碑入账步可能与切换步相差一个控制步。
8. checkpoint 恢复 actor（含观测归一化），切换 eval 模式，并检查评估前后归一化统计严格不变。
9. 当前 reset 是固定仰面姿态，多种子只覆盖采样差异，不构成初始姿态泛化试验。
10. 不满足完整回合条件就报错，不把未完成样本伪装成完整统计。

## 平滑性诊断字段

- `action_delta_l1_sum` / `action_delta_l2_sum`：已裁剪动作的一阶变化，与现有平滑成本同口径。
- `target_delta_*`：变化量乘 action scale 后的关节目标变化，单位 rad 或 rad²。
- `initial_action_delta_l2_sum`：首步从默认目标跳到支撑位的变化。
- `ongoing_action_delta_l2_sum`：排除首步后的变化。
- `action_second_difference_l2_sum`：二阶动作差分；用于辅助识别抖动，不是频谱分析。
- `policy_mean_delta_l2_sum`：分布均值的变化，与实际采样动作变化对照，区分均值颤抖和探索噪声。
- `policy_std_mean`、四个脊柱的 `policy_std_*`、`policy_entropy`：策略分布指标（裁剪前）。
- `spine_rmse_rad`：四个脊柱关节分别对下发前参考目标的跟踪 RMSE，包含终止步。
- `same_trajectory_return_without_smoothing`：仅从既有轨迹回报中扣除 L1/L2 惩罚，不代表移除惩罚后重新训练。
- `metrics_mean` 内的瞬态项也除以整个回合步数；需要累计量时乘 `steps`，不要把它理解为仅对非零事件求均值。

## 已核实的机制与待验证的调整建议

当前 RSL-RL 的 PPO 返回实际平均熵，通用 logger 将其显示为 `Mean entropy loss`。
优化项为 `-entropy_coef * entropy`。因此日志越来越负确实表示熵下降，但不能据此判断过拟合。
高斯微分熵可为负，而且熵只描述分布宽度，不描述策略均值随时间是否平滑。

现有 L1/L2 对缩放前 action 求差，按关节求和，课程内部系数均为 0.1，外部系数均为 1。
同样的关节目标变化，action scale 从 0.5 改为 0.3 后，L1 增强 5/3 倍、L2 增强 25/9 倍。
其中 L1 会惩罚必需的大幅目标变化，L2 还会显著惩罚启动跳变和快速回收；并不是只惩罚高频颤抖。
采样动作 `a=μ+ε` 时，忽略相关性和裁剪，单关节差分平方期望包含 `Δμ²+σ_t²+σ_{t-1}²`。
因此平滑惩罚既约束动作均值，也直接压制探索噪声，容易与翻正初期的探索需求冲突。

建议按顺序做实验，不同时修改全部变量：

1. 先检查直接参考是否成功，以及成功/失败轨迹的总回报和折扣回报排序；失败活满回合所得正奖励不能忽视。
2. 保留现有组作对照；候选训练组先关闭 L1，仅将 L2 内部系数从 0.1 降到 0.003～0.01。腿、脊柱同倍率，不改变关键扭转关节相对权重。
3. 先保持 entropy_coef=0.01、能耗、参考时序和动作缩放不变，验证弱平滑是否能同时保留 S1/S2 探索和减少颤抖。
4. 若确定性成功率稳定，再渐增 L2；例如从 0.005 增至 0.01，再试 0.03。每档都用同一评估集合检查成功率，下降则回退。数值是待验证起点，不是已证实最优值。
5. 若仅随机采样颤抖、均值策略平滑，可在成功稳定后再单独尝试降低熵系数；若均值本身颤抖，降低熵不能替代平滑约束。
6. 不优先加硬低通滤波，避免引入时延破坏目前较短的回收段。后续可考虑参考残差控制或残差平滑，但属于另一项实现变更。

本次未应用上述训练参数建议；需在公平对照结果基础上选择下一项训练实验。

下一轮建议先作弱平滑消融，并从相同初始模型、相同种子开始：

- A：现有 L1=0.1、L2=0.1。
- B：L1=0、L2=0.1，隔离 L1 的作用。
- C：L1=0、L2=0.005，测试减弱 L2 后是否保留翻正探索。
- 以上均指课程内部系数；外部 reward weight 保持 1。其余奖励、熵系数、动作缩放和时序不变。
- 若预算有限，可先比较 A/C，但不能单独归因于 L1 或 L2。
- 若弱平滑下四个脊柱 std 仍过早收缩，再单独测试所有关节统一的 std 下限（如 0.05～0.1 action，需验证），不修改关键扭转关节奖励权重。

## 新增实验：脊柱目标指令跟踪成本

本轮在当前 B 组基础上，仅新增 `spine_target`，不同时进行上述弱 L2 消融。

- 公式：`-2.0 * mean((q_cmd_spine - q_ref_spine)^2)`，四个脊柱关节等权。
- `q_cmd = action_term.raw_action * action_term.scale + action_term.offset`，取动作项及 XML 限幅之前的目标，不用实际关节角代替。
- `raw_action` 已经经过训练 wrapper 的全局 action 裁剪，不代表未经裁剪的 PPO 原始样本。
- 权重 2.0 在 `SQuRo_Backup_env_cfg.py` 的 `rewards["spine_target"]` 设置；函数本身只返回负均方误差，RewardManager 再统一乘权重和 dt。
- 现有实际角/速度模仿、L1=0、L2=0.1、熵系数、动作缩放、T2 时长和 PPO 参数不变。
- 日志自动增加 `Episode_Reward/spine_target`，最优为零，负值表示目标指令偏离参考。旧 checkpoint 的总回报因此不能直接与新训练比较。
- 优先观察：T1 末侧摆/俯仰目标是否减少超限；T2 是否回收侧摆/俯仰并保留扭转；S1/S2 到达率是否改善。
- 建议从头训练以做对照。2.0 是待验证权重，不能保证收敛；该项也会压制探索噪声和偏离参考的动力学补偿。

观测/动作维度不变，旧 checkpoint 的网络形状兼容；是否从零训练或续训应按实验对照目的选择，不能把追加预算带来的改善全部归因于本改动。

## 新实验：阶段单向 + 动作超限成本 + T4 参考连续化

本轮针对"已进入 S1/S2 但始终进不了/留不住 P3"的失败做三项改动。

### 实测诊断（两次训练的录像 CSV + tensorboard 标量）

| 指标 | 旧 run 2026-09-15_22-22-27 @2999 | 新 run 2026-09-16_12-25-52 @2000 |
| --- | --- | --- |
| `s1_awarded` | 0.926 | 0.802 |
| `s2_awarded` | **0.869** | **0.001** |
| `s2_transition` / `back_to_p2` | 0.0089 / 0.0085（相等 ⇒ 极限环） | 0 / 0 |
| `backup_phase` | 1.065（P2/P3 之间来回） | 0.166（赖在 P1） |
| 单步奖励（剔除里程碑脉冲） | T1 0.150 / T3 0.206 / T4 0.159 | T1 0.189 / T3 0.169 / 无 P3 |
| 姿态 | 俯卧 39.6%，height max 0.052 | 俯卧 **0%**，`uprightness` max 0.259 |

两个根因：

1. **参考随阶段切换 ⇒ 各阶段可赚分不同。** 旧 run P2 每步 0.206 > P3 每步 0.159，10 s 回合差 ≈48 分，比 `milestone_success`(35) 还大；策略于是主动摆回 S1 姿态触发 `back_to_p2`，`s2_transition` 与 `back_to_p2` 速率相等，4 s 录像里跑了 5 个来回。新 run 则是 P1(0.189) > P2(0.169)，走 `back_to_p1` 赖在 P1。
2. **执行器指令长期饱和，腿失去控制权。** `ctrlrange` 之外的指令被 MuJoCo 直接丢弃；策略确定性输出为腿 −26~−47、颈 ±25~39，而 `scale=0.3`、所需最大动作只有 5.233，clip=6 的余量仅 1.15×。8 条腿 + 2 个颈关节 100% 时间处于饱和，站起必需的腿伸展无法产生。

此外上一版把 `progress_s1/s2` 按阶段互斥，使前滚前半程（uF 从 −1 到 0）在 P2 里零奖励，并在 P2 入口制造 3/s 的悬崖。

### 改动

- 阶段推进单向：只保留 `advance1`/`advance2` 与阶段内超时重试，取消 `back_to_p1`/`back_to_p2`。

## 新实验：里程碑加权 + 新增 S1/S2 区间奖励

本轮只改奖励权重与新增两个区间项，不动参考时序、状态机判据、PPO、动作缩放和物理参数。

### 改动清单（权重仍在 `mdp/curriculums.py` 的 `_CURVES` 唯一管理）

- 一次性里程碑：`weight_milestone_s1` 2→10、`weight_milestone_s2` 3→15、`weight_milestone_success` 10→35。
- 新增区间奖励 `progress_s1` / `progress_s2`，权重均为 3.0。
- 未改动：`mimic_pos` 10、`mimic_vel` 5、`spine_target` 2、`height` 5、L1/L2 各 0.1、`energy` 0.1。

### 区间奖励定义

复用已有的背腹标记 site 方向余弦 `u`（belly→back 的世界 Z 分量，+1 正置、-1 倒置）：

- `ramp(u, s) = clamp(s*u, 0, 1)`，原点取 `u=0` 而不是 `±cos45°`，保证初始姿态就有非零梯度。
- `progress_s1 = min(ramp(u_F, -1), ramp(u_H, +1))`：前段保持仰面 + 后段翻到俯卧，即朝 S1 的进度。
- `progress_s2 = min(ramp(u_F, +1), ramp(u_H, +1))`：两段都翻到俯卧，即朝 S2 的进度。
- 姿态无效（site 退化或非有限）按 0 计，不产生奖励。
- 与里程碑的分工：里程碑是"每回合首次达标"的一次性脉冲，区间项是连续引导信号，两者不互相替代。

因为初始姿态 u_F = u_H = -1，两个 min 都取到 0：**仰面躺的区间项读数恒为 0**，不构成"不动也拿分"的底分。

| 纯开环跟踪参考 | 248.77 | 21.20 | 276.00 | 545.97 |

单回合口径（`measure_progress_reward_scale.py`，理想开环跟踪）：
`∫progress_s1 dt` ≈ 2.06 s（λ=1）/ 1.65 s（λ=3），`∫progress_s2 dt` ≈ 4.15 s / 3.60 s。
乘权重 3 后区间项约 18.7，占理想密集项（约 204）的 8.5%。

结论：3.0 不会压过模仿/高度项；也不会让"翻正后趴着不动"胜过完成站起

## 新实验：站立成功加入稳定性判据（先治抖动，不碰参考时钟）

### 定位：抖动的主因不是探索噪声

把 `entropy_coef` 从 0.01 降到 0.003、并从 `model_600` 续训后，σ 由 3.030 降到 0.759 后保持平稳，
`Episode_Reward/action_L2` 同步缩小约 10~20 倍（−7.199 → −0.36，与 σ² 比值一致）。
但同一批**权重无关**量的确定性回放对比显示，站立抖动只改善了约 1/3：

| 站立窗口指标 | 600（对照） | 降熵后 800 | 旧 900 |
| --- | ---: | ---: | ---: |
| 14 关节速度 RMS (rad/s) | 2.14 | 4.21 | 5.33 |
| 脊柱关节速度 RMS (rad/s) | 1.51 | 5.22 | 6.88 |
| 腿部力矩饱和比例 | 20.8% | 47.0% | 74.7% |
| 限幅后目标角相邻步变化 RMS (rad) | 0.040 | 0.150 | 0.482 |

⇒ 探索噪声只是抖动的一部分，继续降熵收益有限。

### 根因：成功判据不要求"站住"，而里程奖励奖励"早"

原成功判据只有几何条件（两段背腹余弦 > 0.9、各自高度 > 0.05）连续 0.5 s。
"翻过去 + 顺势弹起"的瞬间就能满足并结算；而里程碑按**达成时刻**发放（`60·γ^T`），
越早越赚 ⇒ "快而猛"严格优于"慢而稳"。
实测同代策略赶时间在里程项净赚 +27.9、在稠密项只亏 −34.5，**净差仅 6.6**，
所以只在 P3 追加平滑惩罚必然被探索收益盖过去。

### 改动：把"站稳"写进成功判据

| 项 | 值 | 说明 |
| --- | --- | --- |
| `STAND_VEL_MEAN_MAX` | 3.5 rad/s | 站立窗口内**平均**关节速度（14 驱动关节瞬时 RMS 的窗口均值）上限 |
| `STAND_UPRIGHT_COS_STAY` | 0.8 | 维持窗口用的宽松几何门限（结算侧仍为 0.9） |
| `STAND_MIN_HEIGHT_STAY` | 0.045 m | 维持窗口用的宽松高度门限（结算侧仍为 0.05） |
| `STAND_CONFIRM_DURATION` | 0.5 → **1.5 s** | 必须真正维持住，顺带把回合长度从 114 步抬到 ≈265 步 |
| `weight_stand_still` | **3.0** | 新增 P3 静止奖励，线性核 `(1 − vel_rms/6).clamp(0,1)`，与判据共用同一个速度量 |

阈值 3.5 的标定依据就是上表：600 的 2.14 明显合格、降熵后的 4.21 明显不合格，
即"要求回到 600 的静止程度，但不必更好"。

**判据必须用"窗口均值"而不是"连续达标时长"——第一版就是在这里翻车的**。
第一版写成"连续达标 1.5 s + 短暂掉出按 2 倍侵蚀"，实测 219 轮 `stand` 终止项全程为 0。
根因不是阈值太严（`Progress/stand_vel = 3.21` 已低于门限 3.5），而是结构性不可达：

```
设 d = 严格达标瞬时占空比, k = 侵蚀倍率 = 2
每步净漂移 = d·dt − k(1−d)·dt  ⇒  只有 d > 2/3 计数器才可能增长
要在 P3 的 ~900 步内攒满 1.5 s 需要 d ≥ 0.72
实测 d = Progress/standing = 0.55, Progress/stand_hold = 0.094 s (目标 1.5 s)
```

均值形式一次解决三件事：窗口内任何一次剧烈抖动都直接抬高 `V/T`，所以**骗不过去**
（"多次短暂达标拼接"这条路不存在，`enter/stay`、侵蚀倍率、宽限预算整套机制全部删掉）；
**没有占空比悬崖**，任意 `d` 下都有梯度；量的正是"这段窗口里抖得有多厉害"。

**为什么用奖励而不是"超死区惩罚"**：惩罚带死区（低于死区无梯度，策略没理由从 1.0 降到 0），
而且惩罚天然给出作弊路线 —— **不进锥内就不被罚**；奖励形式下不进锥只是拿不到钱。
权重 3.0 的标定：站立窗口内现有密集项合计只有 +0.19/s，而"赶时间"靠 `60·γ^T` 早到红利
实测净赚 6.6，要压过它，静止项在 3~5 s 维持窗口里必须能挣到同量级（约 +1.4/s）。

**为什么不动共享的 `_update_confirmation`**：S1/S2/倒置判据用的是硬清零语义，
改成衰减会同时改变阶段推进与重试规则，属于另一批改动；站立另走一套。

### 验收（不依赖权重，先证可达再谈提升）

| 检查 | 结果 |
| --- | --- |
| CPU 回归（新增窗口均值、清零重启、P3 门控与线性核三项） | 21 项通过 |
| `verify_backup_config` 权重与确认时长一致 | `stand_still` 3.0 = 3.0；1.5 = 1.5，通过 |
| 手调版本 λ=3 能否通过新判据 | 走到 `phase=DONE`，且走的是"训练环境确认稳定站起"分支 |

第三方检查顺带修掉一个隐患：手调脚本原先自己数"几何连续成立步数"，
那套判据比训练宽松，训练判失败时回放仍会打印"稳定站起"，
于是回放失去"目标可达"的验证意义；已改为直接读训练环境的 `stand` 终止项。

新增两项标定日志（**不参与判据**，都只对"窗口已建立"的环境取条件均值）：
`Progress/stand_hold` = 窗口内已累计时长均值，`Progress/stand_mean_vel` = 窗口内平均关节速度均值
（**就是判据量本身**）。前者回答"离 1.5 s 还有多远"，后者回答"离 3.5 rad/s 还有多远"。
`Progress/standing` 仍是严格几何达标的瞬时占比，跨版本可比。按 `mean_std` + `stand_mean_vel`
两个数就能决定是"继续训练"还是"动阈值"，不必再猜。

### 第一版实测（run `2026-09-17_19-19-21_S2_stand_smoke`，600 → 814，已被上面第二版取代）

| 指标 | 600 | 814 | 同区间基线（旧判据） |
| --- | ---: | ---: | ---: |
| `Episode_Termination/stand`（每步） | 0 | **0** | 8.84 |
| `Episode_Termination/timeout`（每步） | 1.57 | 1.65 | 0 |
| `Train/mean_episode_length` | 49.5 | **1000（上限）** | 221 → 114.7 |
| `Progress/standing`（严格瞬时占比） | 0 | 0.552 | 0.445（旧口径只看几何） |
| `Progress/stand_vel` (rad/s) | 0 | **3.22** | — |
| `Progress/stand_hold` (s) | 0 | **0.094** | — |
| `Policy/mean_std` | 0.845 | **0.291** | 0.759 → 0.866（不降） |

**机制生效**：判据量的是**采样后**的关节速度，探索噪声从此有代价，
σ 在 200 轮内从 0.845 崩到 0.291（基线同区间是平的）。
σ 正是 100 Hz 可见抖动的直接来源，所以这条路径正好对准"整体抖动严重"这个问题。

**但拿不到成功**：`stand_vel = 3.22` 已低于门限 3.5，说明**瓶颈不是阈值**，
而是"连续达标 + 2 倍侵蚀"隐含的 `d > 2/3` 占空比门槛（实测 `d = 0.55`、`hold = 0.094 s`）。
于是 `stand` 终止项全程为 0、回合全部走 10 s 超时。
副作用是成功项归零后回合顶到 1000 步，`Train/mean_reward`（+298 且仍在升）
变成"10 秒稠密奖励累计"，与旧 run 的数值不可直接比较。

⇒ 这是新增 `Progress/stand_hold` 判别器当轮就换来的结论：**先量出"判据量离门限多远"，
再决定调阈值还是改结构**；不要看到"一直没有成功"就先怀疑阈值。

**尚不能判断瓶颈**是速度门限还是保持时长，故新增 `Progress/stand_hold` 判别器，
再续 300 轮后按上文规则决定放松哪一侧。**本批不因这次观测就改阈值**——
200 轮内趋势明确向好，此时改阈值会把"判据是否可达"和"阈值是否合适"两件事混在一起。
（该判别器当轮就给出了答案：瓶颈是判据结构而非阈值，见上。）

## 整体架构与设计变更

站立稳定性判据实验补充：成功判据从"几何条件连续 0.5 s"改为
"站立窗口内平均关节速度不超 3.5 rad/s，且窗口时长达到 1.5 s"。
数据流为 `asset.data.joint_vel`（14 个驱动关节）+ 背腹 site 方向余弦 + 两段躯干高度
→ `BackupCommand.standing_metrics()` → `stand_gate()` 产出"维持窗口的宽松几何"与"结算的严格几何"
→ `_update_stand_window`（窗口成立累加 `T` 与 `V = ∫vel_rms dt`，中断则一起清零）
→ `terminations.check_stand_success` 结算 `T ≥ 1.5 s 且 V/T ≤ 3.5`。
奖励层新增 `stand_still`（权重 3.0，线性核，与判据共用同一个 `vel_rms`），
奖励项由 14 项增至 15 项；`events.reset_model` 的计时器清零扩到 `_stand_elapsed` 与
`_stand_vel_integral` 两个缓冲。
观测维度、动作维度、动作映射、物理参数、状态机阶段划分、参考表、PPO 参数与其余奖励权重均不变；
`Episode_Termination/stand` 的语义变严（更难达成），日志新增
`Progress/stand_hold`、`Progress/stand_mean_vel` 与 `Episode_Reward/stand_still`。
变更目的是让"冲得快但抖动"直接失败——里程奖励按达成时刻发放，写进成功判据后无法绕过；
静止奖励则给同一目标提供稠密梯度。


此次变更仅扩展任务奖励层：原有实际关节模仿等奖励保持，RewardManager 新增一项限幅前目标指令成本。
数据流为本步 action → scale/offset 还原目标角 → 与同一步参考计算四脊柱负均方误差 → 加权并乘 dt 后汇总。
观测维度、动作维度、动作映射、物理参数、状态机、PPO 和训练循环不变；日志多出 `Episode_Reward/spine_target`。
变更目的是让执行器限幅隐藏的过量指令及 T2 提前解扭产生可区分的成本，并不构成成功率提升的验证结论。

2026-09-14 补充：阶段状态机从 P1/P2 共用固定等待 0.3 秒改为独立配置（默认 1.0/0.3 秒）。
阶段端点参考保持及成功门控沿用原实现，超时仍为软时钟重试；手调回放与训练共享配置默认值。
环境配置增加 `p1_buffer_s` / `p2_buffer_s`，网络接口与 checkpoint 形状兼容，不扩展奖励或训练循环。

连续姿态确认实验补充：原单步背腹符号、理论时长门控、单向 phase 推进，改为角度范围内连续计时确认、达标即时推进和实际姿态回退。
数据流为背腹 site → 朝向候选与高度条件 → 每环境连续计时 → 阶段推进/回退/超时重试 → 当前阶段参考；首次达标锁存单独供里程碑奖励读取。
奖励函数仍使用原权重和 dt 缩放，只将事件来源从每次前进改为每回合首次前进。T4 侧摆改为零保持，其他轨迹与训练循环保持。

区间奖励实验补充：奖励层新增两个连续项，数据流为背腹 site → 方向余弦 `u` → `ramp` 线性爬升 → 两段取 min → 加权并乘 dt 汇总。
`BackupCommand` 把同一控制步的 `u` 缓存给区间项复用（该缓存每步清空，奖励读取的是本步最新 site 数据），
`_pose_flags` 改为由同一份 `u` 派生，正置/倒置判据的数值含义不变。
观测维度、动作维度、动作映射、物理参数、状态机、PPO 和训练循环不变；日志多出 `Episode_Reward/progress_s1`、`Episode_Reward/progress_s2`。
里程碑权重也同步上调。旧 checkpoint 的网络形状仍兼容，但其总回报不能与新配置直接比较。
