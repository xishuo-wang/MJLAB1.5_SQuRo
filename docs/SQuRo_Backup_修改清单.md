### 问题定位（先量化，不改代码）

同一批**权重无关**量的确定性回放对比（站立窗口 = `stand_confirm_elapsed > 0.1 s`，λ 固定，排除重置帧）：

| 指标 | 600（对照） | 新 800 | 旧 900 |
| --- | ---: | ---: | ---: |
| 14 关节速度 RMS (rad/s) | 2.14 | 4.21 | 5.33 |
| 脊柱关节速度 RMS (rad/s) | 1.51 | 5.22 | 6.88 |
| 腿部力矩饱和比例 | 20.8% | 47.0% | 74.7% |
| 限幅后目标角相邻步变化 RMS (rad) | 0.040 | 0.150 | 0.482 |
| 站立窗口步奖励（未加权） | +0.2764 | +0.1871 | +0.1159 |

**结论**：降熵确实压住了探索噪声（σ 3.030 → 0.759 并保持平稳，`action_L2` 同步缩小约 10~20 倍），
但**站立抖动只改善了约 1/3**（脊柱 6.88 → 5.22），离"站稳"很远。
⇒ **抖动的主因不是探索噪声**，继续调熵或平滑权重收益有限。

**根因**：站立成功判据只有几何条件（两段余弦 > 0.9、各自高度 > 0.05，连续 0.5 s）。
"翻过去 + 顺势弹起"的瞬间即可满足并结算；而里程奖励按**达成时刻**发放（`60·γ^T`），
越早越赚 ⇒ "快而猛"严格优于"慢而稳"。
实测同代策略赶时间在里程项净赚 +27.9、在稠密项只亏 −34.5，**净差仅 6.6**，
所以只在 P3 追加平滑惩罚必然被探索收益盖过去。

### 已撤回：判据的第一版实现（"连续达标 + 2 倍侵蚀"）

第一版写成 `STAND_VEL_RMS_ENTER/STAY` 双阈值 + 短暂掉出按 `STAND_CONFIRM_DECAY = 2.0` 侵蚀。
实测 219 轮 `stand` 终止项**全程为 0**。复盘结论：问题不在阈值（`Progress/stand_vel = 3.21`
已低于门限 3.5），而在**判据结构隐含了一个占空比门槛**：

```
设 d = 严格达标瞬时占空比, k = 侵蚀倍率 = 2
每步净漂移 = d·dt − k(1−d)·dt  ⇒  只有 d > 2/3 计数器才可能增长
要在 P3 的 ~900 步内攒满 1.5 s 需要 d ≥ 0.72
实测 d = Progress/standing = 0.55, Progress/stand_hold = 0.094 s (目标 1.5 s)
```

⇒ 判据**结构上不可达**，成功里程碑恒为 0、回合全部走 10 s 超时。
改成窗口均值后这套机制（`enter/stay`、侵蚀倍率、宽限预算）**全部删除**：
均值形式下"多次短暂达标拼接"这条路不存在，因为窗口内任何一次剧烈抖动都会直接抬高 `V/T`。

**教训**：写"连续达标 N 秒"类判据时，先算清楚它对占空比的要求，
再确认当前策略的占空比是否够得着；否则会得到一个永远拿不到的成功条件。

### 本批边界

- **不动**共享的 `BackupCommand._update_confirmation`：那套是 S1/S2/倒置判据用的硬清零语义，
  改成衰减会影响阶段推进与重试规则。站立另走一套。
- **不全局加大** `action_L2`/`action_L1` 权重、**不恢复** `clip_actions`；静止奖励是**P3 专属**的，
  且用"奖励"而不是"惩罚"（惩罚会给出"不进锥就不被罚"的作弊路线）。
- **不动**参考时钟与结算层（问题 1）：不引入 `t_cycle`、不改里程碑发放时刻、不动 `stand` termination 的 `time_out=True`。
- **不动** γ、回合长度、rollout 长度、网络结构与 PPO 其他参数。
- **不动**参考表、状态机阶段划分、S1/S2 判据与其余奖励权重。
- 阈值改动的风险是"成功变得不可达 ⇒ 里程碑归零 ⇒ 策略退化"。
  这是可回滚的单点常量（`mdp/timing.py`），先看 `Progress/stand_mean_vel`（判据量本身）
  与 `Policy/mean_std`，再决定收紧还是放松；`Progress/stand_hold` 回答"窗口时长够不够"。
- 用手调回放（λ=1/λ=3）作为"目标可达"的可行性闸门；回放必须与训练**同源**才有意义。
- 新增 `stand_still` 奖励**只作用于 P3**，且用奖励而不是惩罚；它同时是"判据可达性"的加速器
  （给同方向的稠密梯度），不是判据的替代品。

## 1. 需要你先拍板的决策

### 【待决策 D1】论文是否要求"按参考节奏翻正"？

- **要求** ⇒ 实施 A1（参考改时间驱动），节奏由密集项强制。
- **不要求**，只要求"能翻正站起" ⇒ **跳过 A1**，只做 A2（取消提前红利），接受"快一点也可以"。

> A1 会推翻 `c092f39` 定下的"姿态触发推进 + 超时重播"哲学（让机器人准备好就进下一阶段），改为"必须按参考节奏走"。这是任务定义层面的选择。

### 【待决策 D2】成功奖励与中途复位的触发点

| 选项 | 内容 | 后果 |
| --- | --- | --- |
| **选项 1（推荐）** | 复位挂在**循环末端**（参考时钟走完） | "尽快复位"的激励从根本上不存在；循环长度固定 |
| 选项 2 | 复位挂在"站上那一瞬"（原始提法） | 会把"尽快站上"变成"尽快复位"，**比现状更强** |

### 【待决策 D3】折扣 γ 是否调整

现状 `γ = 0.99^0.5 = 0.99499`/步 ⇒ **每秒 0.605，有效视野 2 s**，而 λ=3 的参考需要 4.4 s。
**视野短于任务时长**，agent 天然短视。候选：`0.999^0.5`（视野 ~4 s）或 `0.999`。
属独立对照项，会影响 GAE 偏差/方差与 PPO 稳定性，**不建议与 A 批同时改**。

### 【待决策 D4】回合长度与 rollout 长度是否调整

- 一个循环 = `2.5λ` = 5~10 s（λ∈[2,4]），当前回合 10 s ⇒ 一回合只装 1~2 个循环。
- `_STEPS_PER_ITER = 96`（0.96 s）**远短于一个循环**，GAE 几乎全靠 bootstrap。
- 候选：`episode_length_s` 10 → 20 s；`_STEPS_PER_ITER` 96 → 200~400。
- 同样属独立对照项。

## 2. 修改项清单

### A 批：参考时钟与结算层（核心，A2~A5 必须一起改）

#### A1 【待 D1】参考改为时间驱动

- **目的**：让"跑快"在密集项上有代价，恢复参考的时间语义。
- **内容**：
  - `mdp/command.py`：新增每环境 `t_cycle`（实际秒）与每循环重采样的 `lam`；`t_nom = clamp(t_cycle / lam, 0, REFERENCE_TOTAL_TIME)`。
  - `phase` 改由 `t_nom` 分区：`< P1_END → 0`、`< P2_END → 1`、`else 2`。
  - `mdp/reference.py`：`_stage_t_nom` 退化为 `clamp(t_cycle/λ)`；删除 p1_t/p2_t/p3_t 分段与 `p2_endpoint` 专用表（P2 的"保持"由时间自然产生）。
  - `_update_command` 中删除 `advance1/advance2` 对 `phase` 的写入。
  - **保留** `p1 = (phase == 0)` / `p2 = (phase == 1)` 布尔，供里程碑窗口判定使用。
  - `retry1/retry2` 随 A1 一并停用（循环长度固定，超时重播不再有意义）；这同时使 **D1（重试参考平移）自动消失**。
- **验收**：确定性回放里"实际到达 S1 的时间"应接近 `0.8λ`（λ=3 时约 2.4 s），而不是 0.26 s。
- **风险**：高。若策略暂时达不到姿态，密集奖励会长期偏低，需要 λ 课程与足够训练量兜底。**这也是 D1 必须先决策的原因。**

#### A2 里程碑改为"锁存 + 定时结算"

- **目的**：消除"提前完成"的折扣红利（即你提出的离散奖励数值问题）。
- **内容**：
  ```
  achieved_s1 = 锁存(S1 姿态连续保持 pose_confirm_s)      # 每循环一次
  settled_s1  = 一次性
  pulse_s1    = achieved_s1 & (t_nom >= P1_END) & ~settled_s1
  ```
  S2 同理，窗口为 `t_nom >= P2_END`。
  - `_s1_awarded` / `_s2_awarded` 语义从"已发放"拆成"已达成"与"已结算"两个标志。
  - 奖励函数（`compute_s1_milestone_reward` 等）读取的脉冲接口不变，**权重不变**。
  - 若姿态达成晚于参考末端，则在达成那一刻结算（只取消"快"的红利，不惩罚"慢"）。
- **验收**：确定性回放里 S1/S2 的入账时刻应分别落在 `0.8λ` / `0.95λ` 附近，而不是 0.26/0.48 s。
- **风险**：低。不改变量级，只改变发放时刻。

#### A3 成功改为"循环末端保持站立"

- **目的**：让"站住"成为**被要求**的条件；消除"站上即结算"。
- **内容**：
  ```
  success_pulse = (t_nom >= REFERENCE_TOTAL_TIME)
                  & (站立连续计时 >= STAND_CONFIRM_DURATION)
                  & ~settled_success
  ```
  - 站立判据沿用 `command.standing_state()`（两段背腹余弦 > 0.9、各自高度 > 0.05），不新增判据。
  - **配套必须做**：`_update_confirmation` 增加"允许短暂掉出"（衰减而不是清零）。现在任何一帧候选为假就清零，长窗口下会被单帧接触瞬态反复打断。
  - "从站上到参考末端保持站立"自动成为要求，**不需要单独设计保持时长参数**（即原 B1 的目的由本项承担）。
- **验收**：确定性回放下成功入账时刻接近 `REFERENCE_TOTAL_TIME × λ`。
- **风险**：中。若策略无法保持，成功率下降；需先在 λ∈[2,4] 下确认 `model_600` 能保持。

#### A4 中途复位（部分复位）

- **目的**：一回合内多次尝试；避免 `time_out` 自举；避免回合长度博弈。
- **内容**：
  - 新增 `command.resample_cycle(env_ids)`：`t_cycle = 0`、重采样 λ、清确认计时 / `_stand_elapsed` / 锁存与结算标志 / `_last_*`。
  - `mdp/events.py`：把"写仰卧初态"抽成 `apply_fallen_state(env, env_ids)`，`reset_model` 与中途复位共用同一份代码。
  - 触发时机：`t_nom >= REFERENCE_TOTAL_TIME`（循环走完）时，**先结算成功脉冲，再对满足条件的 env 执行复位**。
  - **严禁调用 `env.reset(env_ids)`**：它会重置 `episode_length_buf` 并让 `RewardManager` 结算并清零 episode 累计，等于结束回合。
  - **不动**：`episode_length_buf`、奖励缓冲与 episode 累计、`common_step_counter`、RL 侧状态与观测归一化。
  - 需要一个能对 **env 子集**生效的路径：优先在 `command._update_command` 内直接调用（它已能拿到 env 掩码），避免改动核心 `env.step`。
- **验收**：`Train/mean_episode_length` 回到固定值；确定性回放里一回合内出现多个循环。
- **风险**：中。物理上是状态跳变，需确认不产生异常接触冲量（现有 reset 用 `z=0.024` 贴地，已在实际训练中验证可行）。

#### A5 去掉 `stand` termination

- **目的**：消除 `time_out=True/False` 的两难（自引用自举 vs 提前结束弃值）。
- **内容**：`SQuRo_Backup_env_cfg.py` 的 `terminations` 只保留 `timeout`；`check_stand_success` 不再作为 termination，成功改由 A3 的脉冲承担。
- **影响**：`Episode_Termination/stand` 消失；`Episode_Termination/timeout` 恢复为唯一的终止来源。
- **验收**：日志中不再出现 `Episode_Termination/stand`；出现新的成功结算脉冲。

### B 批：探索成本对照（**不预设结论**）

- **目的**：判断 σ 上升与探索成本、价值目标的关系，决定 L2 与熵系数要不要改。
- **内容**：从同一 `model_600` 分出三条短程对照（各约 200 轮）：

  | 组 | 配置 |
  | --- | --- |
  | 对照 | 原配置续训（`entropy_coef=0.01`、`weight_smooth_L2=0.1`） |
  | 组 1 | 只降 `entropy_coef` 0.01 → 0.003 |
  | 组 2 | 降 `entropy_coef`，且 `weight_smooth_L2` 0.1 → 0.01 |

- **明确**：按你的判断，**不预设 σ 必然下降**（熵项在 loss 中、L2 在奖励中，两者不能直接相减求平衡点；且熵 ×0.3 / L2 ×0.1 的推力比反而变成 3 倍）。是否必须降 L2 由对照决定。
- **验收（权重无关）**：见 §4。

### C 批：动作质量（第二阶段，仅登记，暂不实施）

| 项 | 内容 | 备注 |
| --- | --- | --- |
| C1 | 速度约束形式改造：用 Huber/线性替代已饱和的 `exp(-0.5·mse)` 指数核 | 指数核在高误差区奖励变化极小，给不出足够回报差异；但线性成本会增加持续成本，**不因为"有梯度"就认定更有效** |
| C2 | `last_action` 观测加 `clip` | **独立消融项，不是零风险清理**：会压缩不同大动作、改变已有策略与归一化器面对的分布；动作历史本身可能有助于抑制振荡 |
| C3 | 只在 P3 做针对性动作质量约束 | 必须在 A3 落地后（否则会激励"更快冲过 P3"） |

## 4. 验收指标（全部为权重无关量）

| 类别 | 指标 | 期望方向 |
| --- | --- | --- |
| 记账健康 | `Loss/value` 是否随成功次数上升而**保持平稳**（不再单调上涨） | 平稳 |
| 记账健康 | `Policy/mean_std` 是否停止上涨 | 停止上涨 |
| 时序 | 确定性回放中实际到达 S1 / S2 / 成功的时间，对比 `0.8λ` / `0.95λ` / `2.5λ` | 接近参考 |
| 动作质量 | 站立窗口内未加权 `\|Δa\|` RMS（**不是** `Episode_Reward/action_L2`） | 向 600 的 0.13 靠 |
| 动作质量 | 站立窗口内目标角相邻步变化 RMS | 向 600 的 0.040 rad 靠 |
| 动作质量 | 站立窗口内关节速度 RMS（脊柱/腿） | 向 600 的 1.51 / 2.62 靠 |
| 动作质量 | 腿部力矩饱和比例 | 向 600 的 20.8% 靠 |
| 成功定义 | 成功结算次数 / 循环数；回合长度 | 不再要求回合变长 |

**已废弃的验收方式（曾用过，属循环论证）**：用 `Episode_Reward/action_L2` 从 −50 降到 −5 证明策略变好——权重降 10 倍它就自动降 10 倍。

## 5. 明确不做

| 不做 | 原因 |
| --- | --- |
| 全局加大平滑惩罚 | `action_L2` 已是全部密集项的 2.3 倍、约 4/5 是噪声税 |
| 恢复 `clip_actions` | 裁剪是信息屏障；去掉后腿指令从 −22 回到 −7、超出量降 12.8 倍 |
| 新增 P4 状态机阶段 | 由 A3 的"循环末端保持"承担同样语义，不动状态机 |
| 把抖动归因于仿真精度 | 确定性策略已有目标角振荡证据（站立段每步 0.48 rad、力矩饱和 75%） |
| 未经对照把 `time_out` 改回 `False` | 会重新引入"提前结束弃值"的争议 |
| 一次性改全部变量 | 历史上"权重 + 裁剪"同改导致无法归因 |
