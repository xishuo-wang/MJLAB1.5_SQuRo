# SQuRo_Hole 单板高度课程设计

## 单板几何

训练课程使用原 `HOLE_LAYOUT` 第一块板的几何：中心 X=0.2 m、Y=0、半长 0.015 m、半宽 0.1 m、厚度 0.01 m。`position.z` 表示板底。`HOLE_LAYOUT` 仍保留三块旧板，供旧配置和历史位置表可视化使用；单板配置由 `build_single_hole_entities` 构造。

板体是 mocap 实体。`hole_mocap_id` 按板体名称解析它自己的 mocap 下标；`entity.indexing.mocap_id` 指向框架的空 `mocap_base`，不能用来移动碰撞板。复位后由 `write_hole_bottom_z` 写入板体的 `mocap_pos`。虚拟净空奖励和课程记录读取同一板体高度；验收另用 `geom_pos_w.z` 减去编译模型的半厚度，独立检查真实碰撞板底，防止写读同一个错误下标仍通过。

2026-10-12_22-55-09 训练使用修复前版本 `50c1b9c`：课程场景的单板编译默认板底为 70 mm，错误写入空 mocap 导致物理板始终保持这一高度。该运行记录的 64 mm 等课程档仅是虚拟高度，不能作为对应真实板高的穿板通过率。`9c3450b` 修复后才真正执行逐回合板高采样；旧训练应保留作历史对照，修复后的课程需要重新训练。

## 高度查表规则

规则参数只定义在 `mdp/height_schedule.py`，可视化脚本与训练命令调用同一个 tensor 函数。设板的 X 范围为 `[x1,x2]`，板底为 `h`：

- `L=x1-0.150`、`R=x2+0.100`、`M=(x1+x2)/2`。
- 查表位置统一为 `base_Link` 的世界 X，即 `robot.data.root_link_pos_w[:, 0]`。
- 当 `h>=0.070` 时，基座 X 在 `[L,R]` 内，前后端都取 `h-0.030`；区间外都取 0.055 m。
- 当 `h<0.070` 时，基座 X 在 `[L,M)` 内，前端取 0.020 m、后端取 0.055 m；在 `[M,R]` 内，前端取 0.055 m、后端取 0.020 m。区间外都取 0.055 m。
- 中点立即切到前高后低；外侧左右端点均包含。两个低姿态区间互斥。

两个命令调用同一个 `sample_base_heights`，不再使用前后躯干中心位置或固定中心距偏移决定阶段。脊柱侧摆、俯仰或整体偏航改变两段中心的 X 间距时，仍不能产生双低命令。短板区间为 `[0.035,0.315]` m，中点为 0.200 m；长板预览区间为 `[0.350,0.800]` m，中点为 0.600 m。

基座坐标仅用于高度命令阶段。净空奖励和完整穿出判据仍读取前后躯干的实际位置与采样点。新规则保证命令互斥，不保证实际姿态瞬时达到目标或切换时前躯干已经完全离板，后者需要训练与回放确认。

高板严格使用 `h-0.030`，不设置 0.055 m 上限。板底为 0.090 m 时命令为 0.060 m；参考表仍按当前最近邻高度档选择 0.055 m，不做参考插值。

## 最低高度推进

`HeightCurriculumState` 提供可序列化的统计结构。只接受第四阶段、真实碰撞开启且课程采样启用的有效完成回合；所有合格高度都累计全高度统计，只有采样高度等于当前 `Zmin` 的回合进入最低档批次。未通过就超时、跌倒及其他失败都计入分母；已完成合法穿板、之后未跌倒的 12 秒超时回合仍计成功。每 256 个最低档回合封闭一批，通过率至少 60% 才累计连续达标批次；连续两批达标且当前档驻留不少于 100 iter 后，未来 reset 的 `Zmin` 下调 0.002 m，最低到 0.048 m。`Zmax` 保持 0.090 m。

推进只改变未来 reset 使用的采样范围；已有回合的板高保持不变。checkpoint 状态包括当前范围、驻留起点、批次计数、连续达标批数、各高度总计数和历史批次，可用于续训恢复。

终止监测使用 F/H 各九个 site。穿板时躯干采样点必须全部位于板宽内，板内点不得高于板底（允许 1 mm 数值容差）；经过上方或侧边会分别记录为高度超限或侧绕。成功要求先从前方进入，两个躯干在同一时刻都完全越过板后沿，且回合结束前没有跌倒。合法通过后自然结束的 12 秒 timeout 仍可成功。监测项始终返回 False，不改变原 12 秒终止时间；只有训练课程开启时才更新统计。课程推进在终止监测时同步完成，runner 每步消费回合快照用于日志。

训练阶段 1 为 0～1k iter，阶段 2 为 1k～2k iter；阶段 3 为 2k～3k iter，复制第二阶段的高度池及全部既有奖励参数，仅增加全位置走廊惩罚。3k iter 的阶段 4 开始，runner 一次重建为单板并开启真实碰撞，之后只通过 reset 更新高度，不再重建环境。每回合为 12 秒（1200 步），默认训练预算 6000 iter。交互或无头评估可使用 `uv run python -B -m mjlab.scripts.SQuRo_Hole_curriculum_play --checkpoint <checkpoint> --no-show --steps 2000`；默认固定在 checkpoint 的当前 `Zmin`，指定 `--obstacle-height` 可固定其他合法板高，`--random-height` 则按 checkpoint 当前范围采样。评估不会推进课程，并将完成回合写入 CSV。

主回放脚本 `SQuRo_Hole_play` 中，课程阶段的 `obstacle_height=None` 优先读取检查点高度范围的 `Zmin` 作为板底，显式板高优先；热身阶段以及缺少高度课程记录时沿用保存的布局或配置默认，不能将尚未启用的课程下界当作当前板高。课程阶段的 `schedule` 模式还会将回放采样上下界都设为该最低档，每次复位保持同一板高，课程进度冻结。`fixed`/`random` 命令模式同样使用所选板高，但不会启用高度课程，场景构造和命令逻辑沿用原规则。需要范围随机采样时使用专用课程回放脚本的 `--random-height`。回放和续训必须通过下述命令格式校验。

## 全位置走廊约束

`corridor` 与原有 `body_contact` 是两个独立奖励项。前者从 2000 iter 起启用，3000 iter 后继续保留；前两个阶段权重为零。它分别读取前、后躯干九个 site 的最高世界 Z，不按 X/Y 位置筛选点，也不依赖真实板体的位置。

两段的虚拟上限分别为 `h_F+BODY_HEIGHT_OFFSET`、`h_H+BODY_HEIGHT_OFFSET`，其中 `BODY_HEIGHT_OFFSET=0.030 m` 与高度规则共用唯一常量，不再增加 2.5 mm 容差。例如 20/55 mm 命令对应 50/85 mm 的表面上限；相同高度命令对应相同上限。

超限量为 `e=max(z_max-上限,0)`；走廊项为 `-w * mean(1-exp(-sigma*e²))`，在上限内恒为零，越低不会额外加分。权重 `w=5`、`sigma=2000` 都定义在 `_CURVES`。原高度跟踪奖励继续提供对称目标约束，避免仅靠单侧走廊导致无限降低姿态。

原 `body_contact` 在阶段 4 仍以权重 5 计算板底净空，阈值为实际板底减去 2.5 mm，空间范围与原公式保持一致。真实碰撞不会停用该奖励。此次没有同时修改其空间掩码、角度奖励批次依赖、位置表、模仿配比、脊柱尺度或 PPO 参数。

## 整体架构与设计变更

变更涉及任务命令、策略输入含义、奖励项及阶段切换时机，框架和 PPO 算法不变。旧命令为 `[vx,vy,vz,h_F,h_H,angle]`；新命令为 `[vx,h_F,h_H,gait_frequency,curvature,obstacle_height]`，前五列与 Backup 的顺序一致。策略观测仍为 113 维、动作仍为 14 维，但命令列含义已经改变，旧网络不能直接加载后继续训练或回放。

`config.py` 唯一定义列名、槽位、命令版本与四阶段边界。`HoleCommand` 写入速度、目标高度、固定 2 Hz 步频、固定零曲率及板高先验；现有姿态奖励使用的零角度目标独立保存，不占命令列。参考生成读取步频列计算相位，并按步频比例输出关节速度。

板高先验参照 Backup：有实体时记录其真实位置，只有没有实体时才写零。前三阶段保留三块无真实碰撞的旧板，先验为第一块板的实际板底，默认 0.050 m；第四阶段记录逐环境的真实单板板底。写入、部分复位、周期更新及外部板高修改后，观测均由同一板体读取。

数据流为 `mocap板体 → 板高先验/高度查表 → 六维命令 → 参考与策略观测 → 策略动作`；奖励分别读取完整躯干采样点、实际板底及目标高度。runner 在 3000 iter 重建场景，保留训练步数与课程状态，并重新取得观测。

新检查点 `hole_state.version=3`，同时保存 `command_schema_version=2` 和 `command_fields`。回放与续训在加载模型前检查版本及完整列名；缺少信息或列序不一致时明确拒绝。旧检查点可在其训练时版本（如 `1d25a45`）继续回放，本次训练必须从头开始。

默认 Metrics 保留前后高度误差、前向速度及误差、四种高度模式占比、两种单低模式的前段方向误差、侧向速度绝对值、走廊超限、实际板底净空超限，以及课程最低档、成功率、样本数和失败分类。真实碰撞阶段由原 56 项降至 26 项。起点、位移极值、每种模式的多套速度/朝向、批次内部计数等默认不输出；诊断脚本可设置 `log_detailed_metrics=True`。

## 训练与验收

从头训练使用 `uv run train Mjlab-SQuRo-Hole --agent.logger tensorboard`。前三阶段既有奖励参数对应原第一、第二、第二阶段；第四阶段对应原真实碰撞课程参数。新增走廊在第三、第四阶段生效，其他训练配置保持不变。

新增验收入口为 `uv run python -B -m mjlab.scripts.Hole.verify_hole_corridor_commands`，覆盖阶段边界、第三阶段参数等效、最高点单侧惩罚、无位置门控、命令观测列序、参考步频、独立碰撞几何板高、部分复位及检查点格式拒绝。

2026-10-13 本次验收：新增走廊命令、基线、碰撞、课程、命令复位及命令诊断全部通过，Backup 阶段奖励 88 项回归通过。16 个 CUDA 环境分别从 1999、2999 iter 各短训 3 轮：2000 边界不重建，3000 边界只重建一次，碰撞几何与板高命令一致，新检查点可由独立回放 runner 加载。与 `1d25a45` 独立对照，28 项原有参数按第一、第二、第二、第三段等效映射；54 组高度/相位下的 2 Hz 参考位置及速度逐元素相同。复现脚本与日志位于 `logs/hole_change_audit_20261013/`。

主回放入口还验证了热身默认板高、课程最低档、显式 62 mm 板高、固定与随机命令共五种工况，每种连续三次 reset 的真实碰撞几何与板高先验一致。课程检查点保存的是单板布局，固定与随机命令回放也保留该单板。真实旧检查点会在创建环境之前被命令格式校验拒绝，验收未启动窗口。
