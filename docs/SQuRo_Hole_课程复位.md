# SQuRo_Hole 位置表复位修复

本文记录历史位移表的起点修复。当前高度课程已经使用基座世界 X，旧表已移除；起点仍供位移诊断使用。现有复位验收覆盖当前单板规则的进入、中点和离开边界，并验证非零起点不会移动世界坐标边界；当前训练与验收以 `SQuRo_Hole_高度课程设计.md` 为准。

## 训练现象与根因

`2026-10-12_15-56-30` 训练归档为 `2f365fb`。
1900 轮的后低工况可稳定推进；2900 与 3999 轮在同位置表、同板几何、无碰撞的
10 秒回放中分别左转约 85°、94°，1900 轮约为 1°。
训练后期的定时检查全部为前低后高，后低模式没有出现在这些检查样本中。

复位事件写入根 qpos 后，command.reset 会重新记录位移起点；
此时 sim.forward 尚未执行，root_link_pos_w 读取的 xpos 仍是复位前的位置。
真实环境从 x=0.7 复位到 x=0 后，旧起点仍为 0.7，
后低段的 0.2 米相对阈值因此要到实际 x=0.9 才触发。
后续回合反复采集旧终点，位置表与固定板的绝对位置失配，训练模式覆盖随之改变。

## 本次改动

起点改读已经写入的根 qpos 位置，用 robot.indexing.free_joint_q_adr 解析字段。
不依赖 sim.forward，也不把复位位置假定为零。
只修复任务层的起点读取，不调整框架复位顺序或增加前向计算。
位置表内容、奖励权重、σ、参考姿态、观测/动作维度和 PPO 配置沿用原值。

这是命令课程行为修复，不能继续宣称完整训练轨迹与 `929a2a3` 数值等价。
原有参考表和给定命令下的奖励数值仍按既有验收验证。

## 验收

```powershell
uv run python -B -m mjlab.scripts.Hole.verify_hole_command_reset
```

- 从多个非零旧位置、负位置连续复位，起点必须等于实际复位位置。
- 部分环境复位不改其他环境的起点或状态。
- 复位后覆盖位置表的主要切换边界，包括 0.2 与 0.32 米。
- 经 env.step 触发异步超时，复位环境必须正确进入第一段位置表。
- 在复位事件中写入非零位置，验证相对位移口径而非固定零点。

## 后续训练

优先从 `model_1900.pt` 续训，观察位置表阶段是否恢复后低模式覆盖和直行能力。
先验证课程修复，再决定是否调整侧向速度或左右推进约束。
修复已确认起点错误；能否恢复完整策略表现仍需用户训练验证。

## 训练诊断日志

日志在 sim.forward 和位置表更新之后记录当帧状态，不修改奖励或观测。
指标保留为独立张量，逐步采样不会把历史值覆盖；避免逐项转为 Python 数值造成 GPU 同步。

四种模式的 TensorBoard 前缀为 `Metrics/双高`、`Metrics/前低后高`、
`Metrics/前高后低`、`Metrics/双低`，每种模式只记录以下指标：

| 指标后缀 | 含义 |
| --- | --- |
| `占比` | 当帧该模式的环境比例 |
| `前躯干方向误差均值_度` | F 物理前向相对世界 +X 的绝对角误差，仅两种单低模式记录 |

另记录 `Metrics/课程/阶段` 与 `Metrics/运动/侧向速度绝对值均值`。

F 段 yaw 减 π/2、H 段 yaw 加 π/2，再折回 ±π。
无样本的模式占比和均值记录为零；占比零不代表该模式表现良好。

原先按模式分组的 `样本数`、`相对X均值`、`前向/侧向速度均值`、
`后躯干方向误差均值_度` 以及 `Metrics/位移/*` 已随
`log_detailed_metrics` 开关一并删除，不再输出。
